# コードモード（シークバーにコードを表示）

v4.27.0のプロトタイプ。読み込んだ曲の和音を解析し、シークバーの波形の代わりにコード名のブロックを表示する。

## 使い方
- 設定帯(波形エリア下 / SPはMore内)の**View**で`Wave`⇔`Chord`を切替。Settings>Seek barにも同じ項目(View / Chord detail)。
- Chordにした時だけ解析が走る(波形モードのままなら何も計算しない)。解析中は波形を薄く出し、Viewに進捗%が出る。終わるとコードに切り替わる。
- マーカー(線・番号・メモのラベル)・A/B・区間ハイライトは行のDOMなのでそのまま出る。**色**は波形と同じ規則(最後に通過したマーカーの色。再生済み=濃い、未再生=薄い。マーカー無しはアクセント色)でブロックに塗る。

## 仕組み
- `player-ui-shared.js`の`decodeWaveform`が波形用にデコードした結果(8kHz前後)を`QNChords.offer(id, audioBuffer)`へ渡す(追加のデコードなし)。`loadFile`は`QNChords.reset()`で前の曲の解析を捨てる。
- `QNBars.setViewMode("chord")`→`QNChords.ensure()`→`qn-chord-worker.js`が`QNChordCore.chroma()`(STFT約0.5秒窓・hop約0.13秒→ピーク抽出→チューニング補正→12音クロマ)。
- 結果のクロマは曲ごとに最大3曲ぶんメモリに保持。`QNChordCore.classify()`(テンプレート照合＋キー推定＋Viterbi平滑化)はメインスレッドで実行(軽い)。Chord detailを変えた時はclassifyだけやり直す。
- 詳細度: `basic`=maj/min、`extended`=+7/maj7/m7/dim/sus4(既定)。表記は推定キーで#/♭を決める。
- 描画: `player-bars.js`の`paintChordRow`。ブロックは行の端で切れる側だけ角丸なし。幅に収まらないコード名は根音だけ→それも入らなければ非表示。コード無し/無音は細い線。

## 既知の限界(プロトタイプ)
- 拍・ベース音・転回形は見ていない(スラッシュコードなし)。窓が長いので切り替わり位置は±0.25秒ほどずれうる。
- 検証は合成音源(ギター風の倍音＋ドラム/ノイズ＋単音メロディ)のみで、判定は約99%一致。実際の曲(歌・ミックスの厚い音源)では下がる。
- 解析結果は保存しない(曲を選び直すとキャッシュ外なら再解析)。手動でのコード修正は未対応。
- 端末負荷: 4分の曲でクロマ抽出は約1〜2秒(PC)。Workerが作れない環境ではメインスレッドで実行(固まる)。
